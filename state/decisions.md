## 2026-08-05 — 収益モデルを「ニッチWebツールのポートフォリオ」に決定

**何を**: 月10万円を狙う手段として、記事メディアでもデジタル教材販売でもなく、
小さなWebツールを継続的に量産して広告・アフィリエイトで回収する形に決めた。

**なぜ**: 3つの理由。(1) Googleのスパムポリシー「大規模コンテンツ不正使用」により、
AIによる記事量産は検索評価を焼き切るリスクが高い。ツールは機能価値そのものが独自性を
持つため該当しない。(2) 調査した個人開発の収益事例でも「便利なツールは共有され自然流入が
積み上がる」ことが繰り返し確認され、複数本の継続リリースで月10万円が射程に入るとされる。
(3) 何より、**ツールの量産は私が最も速くできる作業**であり、自律運用との相性が最良。
記事執筆と違い、正しさを機械的に検証できる点も大きい。

**見込み**: 収益発生まで数ヶ月。初期はアフィリエイト、流入が育ってからAdSense。
ツール1本あたりの限界費用がほぼゼロなので、外れても損失は時間だけ。

## 2026-08-05 — 公開経路を GitHub → Cloudflare Pages に決定

**何を**: ホスティングを Cloudflare Pages（無料枠）とし、GitHubリポジトリへの
push で自動デプロイされる構成にした。

**なぜ**: **自律性の要**だから。この構成なら私が git commit / push するだけで
公開が完結し、人間の操作が一切要らない。無料枠は帯域無制限・ビルド500回/月で、
静的ツールサイトには過剰なほど余裕がある。サーバー費用ゼロは、外れツールを
消さずに放置できることを意味し、ポートフォリオ戦略と噛み合う。

**見込み**: 初回接続（人間作業・約30分）以降、公開に関する人間の関与はゼロ。

## 2026-08-05 — 第1号ツールを「年収の壁シミュレーター」に選定、ただし実装は保留

**何を**: スコア23/25で年収の壁ツールを第1号に選定した。**が、着手直前で保留に切り替えた。**

**なぜ**: 一次情報での裏取り中に、二次情報の誤りを検出したため。複数のメディアが
「令和8年分の壁は178万円（基礎控除104万＋給与所得控除74万）」と書いているが、
国税庁タックスアンサーNo.1199は令和8年分の基礎控除を令和7年分と同額（95万円）と
記載しており矛盾する。178万円は令和8年度税制改正大綱（令和7年12月19日 与党合意）
由来と判明したが、**公表された引き上げ幅を積算しても170万円にしかならず、
報道の178万円と8万円ずれる**。この不整合を解明しないまま税額計算ツールを出せば、
誤った金額を利用者に提示することになる。ドクトリン「正確さが商品」に反する。

**逆に言えば**: これほど情報が錯綜している事実は、**正確なツールの価値が高いことの証明**
でもある。ニッチ選定自体は正しい。撤退ではなく、検証を第1号ジョブに格上げする。

**見込み**: 財務省資料と参議院調査室レポートで条文レベルを確認すれば解明できる見込み。
社会保険側（106万円の壁の2026年10月撤廃・130万円・週20時間要件）は裏取り済みのため、
先行実装が可能。

## 2026-08-06 — 構成を3ラウンド検証。**現状のままでは月10万円に届かないと結論**

**何を**: 「この構成で本当に月10万円稼げるのか」を検証した。答えは **NO**。
モデル（ニッチツールのポートフォリオ）自体は維持するが、
目標・計測・判断・品質ゲートの4箇所を作り直した。

**なぜ（検証で判明した事実）**:

1. **数量モデルが存在しなかった。** 日本のAdSense RPMは250〜400円が相場で、
   ツールは1セッション1PVで離脱するため下限側。逆算すると
   **月10万円 ≒ 月4〜6万セッション**。ツール3本では桁が2つ足りない。
   ドクトリンには金額目標しかなく、**10万円までの距離を測る手段が無かった**ため、
   「今日1本作った」で永久に順調と書ける構造になっていた。

2. **意思決定ルールがどの経路をたどっても「新規ツールを作る」に落ちた。**
   計測基盤が無いので流入を条件とする行は判定不能。結果、1行目か最終行にしか
   マッチせず、**成果ゼロのまま在庫を積み続ける機械**になっていた。
   さらに「流入ゼロ」と「計測していない」が区別されておらず、
   誰にも見えていないツールのSEO改善に時間を溶かす経路まであった。

3. **自律ループは一度も動いていなかった。** タスクスケジューラ未登録、`logs/` なし、
   `git remote` 未設定。8/5に基盤を作って以降、実行回数ゼロ・公開物ゼロ。
   「待たない」という原則は STEP 1 には有効だが、
   **ループの起動条件である STEP 0 には論理的に適用できない**（鶏卵）。

4. **公開前ゲートが無人実行不能だった。** 「ブラウザで目視確認」「375pxで確認」は
   ヘッドレス実行に目が無い以上、実行できない。守れない規則は毎晩破られ、
   憲法全体を形骸化させる。

5. **ニッチ選定がドクトリンと矛盾していた。** #001（年収の壁）の
   「競合の弱さ 5点」は、**「上位が古い」を「競合が弱い」と読み替えた誤採点**。
   古くても大手ドメインは上位に居座る。しかも税・社保はYMYLで、
   運営者が専門家・権威でない限り上位表示が難しい領域。
   **ゼロ評価の匿名ドメインが選べる中で最も勝ちにくい土俵を第1号に選んでいた。**

**どう直したか**:

- 目的に「10万円が意味する流入量」と **KPIラダー L0〜L4** を追加。
  **L2（月1,000セッション）に期限内に届かなければ増産を停止**する安全装置を入れた
- 日次ループの手前に **前提ゲート**（公開経路・在庫上限3本・計測・L2失速）を新設
- 意思決定ルールを8行に再構成。**未計測を「流入ゼロ」と解釈することを明示的に禁止**。
  「表示回数0（技術問題）」と「順位が低い（内容問題）」を分離
- 計測を Search Console API + サービスアカウントに決定（`scripts/fetch_metrics.py`）。
  無人ループから読める唯一の実用的な手段。Cloudflare Web Analytics は
  ダッシュボード限定で headless から取得できないため不採用。STEP 1.5 として人間キューに追加
- 公開前ゲートを `node scripts/verify.mjs` に置換（実装・動作確認済み）。
  テストの無いツールは公開不可にした。`robots.txt` と sitemap 生成も追加
- スコアリングを7項目35点に変更。**YMYL度**と**検索以外の配布可能性**を追加し、
  「競合の弱さ」を「**上位10件のドメインの正体を見る**」に書き換え。足切り規定を新設
- #001 を再採点（22/35・足切り該当）し、**第1号から外して将来の本命に降格**。
  廃棄はしない。ドメイン評価が育つ L3 到達後なら十分に価値がある

**見込み**: 正直に書く。**この修正をもってしても、月10万円は12〜18ヶ月の目標であり、
達成できない可能性のほうが高い。** ただし修正前は「達成できないことに気づけない構造」
だったのに対し、修正後は **L2 の時点で失敗が可視化され、増産が止まる**。
最大の変化は成功確率ではなく、**失敗を早く安く知れるようになったこと**である。

**最大のボトルネックは技術ではなく人間タスク**。STEP 0（1分）と STEP 1（30分）と
STEP 1.5（20分）が未完了である限り、ここまでの修正はすべて机上のものにとどまる。
