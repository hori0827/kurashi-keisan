## 2026-08-05 — 収益モデルを「ニッチWebツールのポートフォリオ」に決定

**何を**: 月10万円を狙う手段として、記事メディアでもデジタル教材販売でもなく、

## 2026-08-06 — ランナーが全て文字コードで壊れていた（自律化を止めていた真因）

**何を**: STEP 0 を実行しようとして `register_task.ps1` がパースエラーで落ちた。
調べると `scripts\*.ps1` の3本すべてが **UTF-8 BOMなし**で保存されていた。
全てに BOM を付与して修正し、構文チェックの通過を確認したうえでタスクを登録した。

**なぜ起きたか**: Windows PowerShell 5.1 は BOM の無い `.ps1` を **ANSI(CP932) として読む**。
UTF-8 で書かれた日本語コメントのバイト列が別の文字として解釈され、
引用符や波括弧の対応が壊れて構文エラーになる。

**これが意味すること**: 仮にユーザーが指示どおり STEP 0 を実行していても、
**登録は失敗していた**。さらに `daily_run.ps1` と `weekly_review.ps1` も同じ状態だったので、
登録できたとしても**起動した瞬間に死んでいた**。
つまり自律ループが1回も動いていなかった原因は、
「人間が作業をしていないから」ではなく **こちらの成果物が壊れていたから**である。
SETUP_HUMAN.md には8/5に「登録に失敗していた」と一度書いて修正済みのつもりでいたが、
**修正が効いていないことを検証していなかった**。書いて終わりにせず、実行して確かめること。

**再発防止**: `CLAUDE.md` の環境メモに「`.ps1` は必ず UTF-8 BOM付きで保存する」を明記した。

### 1. 詰まりの具体化 — 「催促」ではなく「作業量そのもの」を減らした

前提ゲートは「STEP 1 を最上部へ再掲し、詰まりを具体化する」と指示している。
しかし**同じ依頼を大きな文字で書き直すのは具体化ではない**。8/5 から2日、
STEP 1 は一歩も進んでいない。原因を「やる気」に帰すのは分析ではないので、
作業の中身を数えた。**4作業・約30分**で、しかも1-1（リポジトリ作成）と
1-2（トークン発行）は**私がAPIで代行できる**ものだった。人間にしかできないのは
「トークンを1個発行して置く」ことと「Cloudflareのアカウントを作る」ことだけである。

そこで `scripts/connect_github.ps1` を書いた。トークンが
`secrets/github_token.txt` に置かれていれば、
**リポジトリ作成 → 公開前ゲート(verify.mjs) → remote設定 → 初回push** までを自動で行う。
`daily_run.ps1` の冒頭からも呼ぶので、**トークンを貼れば翌朝の自動実行で勝手に公開が始まる**。
人間の作業は **2作業・15分**（トークン発行3分／Cloudflare 10分）になった。

設計上の判断を2つ記録する:

- **トークンを remote URL に埋め込まない。** 埋め込むと `git remote -v` の出力や
  `logs/` の実行ログに平文で残る。git標準の credential store
  （`%USERPROFILE%\.git-credentials`）に入れ、remote は素のURLにした
- **初回 push の前にも `verify.mjs` を通す。** 初回 push も公開である。
  ここを例外にすると、検証していない状態が世界に出る最初の一回になる

`.ps1` は UTF-8 BOM付きで保存し、`Parser::ParseFile()` で構文0エラーを確認し、
さらに**実際に実行して**トークン未配置の分岐（exit 2・日本語が化けない）まで確かめた。
8/6 の教訓（書いて終わりにしない）を適用している。

### 2. 第2号ツール「ペンキ・塗料の必要量計算」（29/35）

在庫1本 < 2本だったので、ゲートの許可枠で1本だけ作った。
候補2件（塗料の必要量／照明のルーメン計算）を実際に検索して上位ドメインを確認し、
塗料を選んだ。上位は `jptools.jp` `keisan-tool.com` `mahiroapps.com` `pochitto-tool.site`
と**個人ツールサイトばかり**で、大手メディアも士業法人もゼロ。項目2は5点。
照明側は上位が業者ブログとメディアで、しかも「畳数×400lm」の一次情報が
業界団体の基準にあたる必要があり、当日中の裏取りが不確実だったので見送った。

**なぜ既に4本も競合ツールがある土俵に入ったのか**: 既存の4本はいずれも
「面積 ÷ 固定の塗布面積」を1回やるだけで、**出典を書いていない**。
そして全社が同じ2つの落とし穴を踏んでいる。

1. **塗布量は単一値ではなく範囲である。** カンペハピオ「室内かべ用塗料」の0.7L缶は
   4.9〜7㎡（1回塗り）＝ 7〜10㎡/L で、上下に4割以上の開きがある。
   「8㎡/L」に丸めると、丸めた側の利用者が塗料切れを起こす
2. **「何回塗り基準の面積か」が製品ごとに違う。** アサヒペン「水性多用途EX」の
   40〜50㎡（7L）は**2回塗り**の数字、同社「水性多用途カラー」の 36〜47㎡（5L）は
   **1回塗り**の数字。**同じメーカー内で混在している**。取り違えると倍または半分ずれる

本ツールはこの2点を構造として持ち、さらに**缶の組み合わせ**を出す。
5.3L必要でも5.3Lの缶は無いので、実際には「合計が必要量を超える組み合わせ」を買うことになる。
本数を減らすほど余りが増えるトレードオフなので、**候補を一覧で並べ、選択は利用者に委ねた**。
どれが安いかは実売価格しだいであり、価格は改定が頻繁で裏取りできないため断定していない。
これが他の4本との最大の違いである。

**正確さの担保**: 塗り面積はカンペハピオ1製品・アサヒペン3製品の**公式製品ページから
そのまま転記**（丸めていない）。1回塗り基準の塗布量が
カンペハピオ 7.0〜10.0㎡/L、アサヒペン 約6.9〜9.5㎡/L と**独立に一致**した。
テストにこの「2社突き合わせ」を常設し、片方が製品改定で変われば検知できるようにしてある。
あわせて「同一製品内で缶ごとの㎡/Lのばらつきが1.35倍を超えたら失敗」という
**転記ミス検出**も入れた。桁や単位を写し間違えるとここで跳ねる。

**T002 との関係**: 塗料は開口部を差し引き、壁紙は差し引かない。
**同じ部屋でも材料によって作法が反対になる**という知見を両ツールに相互リンクで書いた。
内装DIYの数量計算という面を取りにいく意図がある。ドメイン評価ゼロの新規サイトでは、
バラバラな1本より関連する2本のほうが主題が伝わりやすい。

**公開前ゲート**: `node scripts/verify.mjs` は exit 0（HTML5枚・ツール2本・
